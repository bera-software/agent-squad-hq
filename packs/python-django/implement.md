# Python / Django — Engineer rules

Project CLAUDE.md and ADRs override these defaults. If the project uses
pytest-django, run `pytest` instead of `manage.py test`.

- Fat models / service functions, thin views. Keep querysets reusable via
  custom managers.
- Forms or DRF serializers validate every input. DRF serializers list fields
  explicitly (`fields = [...]`, never `__all__`) and mark privileged fields
  read-only.
- Use the ORM; for raw SQL use `params=`, never string formatting.
  No `extra()` with input.
- Every schema change comes with a migration generated by `makemigrations`
  and reviewed as high risk. Data migrations must be reversible or say why not.
  Never edit an applied migration.
- Permissions: `LoginRequiredMixin` / `@login_required` / DRF
  `permission_classes` on every non-public view, plus object-level checks
  (filter querysets by the current user/tenant).
- Templates auto-escape; never use `mark_safe` or `|safe` on user content.
- Settings: secrets from the environment; `DEBUG=False`, explicit
  `ALLOWED_HOSTS`, secure cookie flags and HSTS in production settings.
- Avoid N+1 with `select_related` / `prefetch_related`; paginate list views.
- Long work goes to the project's task queue (Celery, RQ, Django tasks), not
  the request cycle.
- Tests: Django `TestCase` or pytest-django; cover anonymous, unauthorised and
  authorised access for new views.
- Run `manage.py check`, `makemigrations --check` and the test suite before
  pushing.

## Quality gates
- Before pushing, run the architecture check `uv run lint-imports --config .importlinter` (the `arch` gate runs it
  whenever `.importlinter` exists) and fix violations in the code. Never loosen
  the rules or add a suppression to get it green; that needs an approved design.
- Run the lint/format check `uv run ruff check . && uv run ruff format --check .` before pushing (the `lint`
  gate); fix the findings rather than disabling rules.
